## 代表项目

### 1. 新一代智能问数 · NL2Data Agent（项目负责人）

**做什么**：让用户用自然语言描述取数需求，Agent 自动把需求翻译成对业务系统的操作，完成数据获取、可视化与解释——一个面向营销数据资产的自然语言取数产品。

**我的定位**：**项目负责人**，主导技术路线选型与一期、二期的从 0→1 全流程落地。

**我做了什么**：

- **一期**：针对业务方接口开放度不足的现实约束，敲定 **GUI Agent + 页面图谱**路线——Agent 直接在前端页面拟人操作、不依赖后端接口，以低接入成本覆盖任意 Web 系统的取数；攻克 GUI Agent 领域公认的元素漂移与视觉幻觉难题，主导构建页面图谱与自动化评估链路，实现云图核心页面的全场景覆盖并达到可上线准确率。
- **二期**：为承接"更快"的产品诉求，主导架构从 GUI 编排全面切换至 **标准化工具调用与命令行体系（Harness / CLI）**，把复杂前端接口工程化为 Agent 可直接调用的 CLI 能力；同时主导建设 **Agent 质量评测体系（LLM-as-Judge）** 作为上线基线，端到端耗时与准确率均显著优于一期，方案被部门内其他 Agent 项目借鉴。

- **数据服务化与权限治理**：将问数能力从单一产品功能升级为可被多个 AI 应用复用的数据服务，支持对话、自动化任务与命令行等入口；解除对页面登录态和会话上下文的依赖，复用业务权限校验，保障跨系统调用的身份与数据访问边界。
- **灵活取数与工具维护**：将固定页面、固定接口编排扩展为跨行业、多维度的数据探索能力；通过动态工具路由与知识检索匹配取数需求，自动识别工具信息和能力范围变化，降低接口扩展与业务接入的维护成本。
- **可靠执行与质量闭环**：建设沙箱复用、运行缓存、并发安全和环境隔离；将用户请求、执行轨迹与结果评审串成端到端评测流程，并通过线上样本回流持续检验实际取数质量。

**技术栈**：Python / Go、LLM、GUI Agent、Harness、RAG、MCP、评测体系（LLM-as-Judge）。

### 2. AI 营销官智能报告（核心开发之一 / "初代目"）

**做什么**：部门首款对客 AI 分析 Agent——用户以自然语言描述业务问题，系统端到端产出可解释的营销诊断报告。

**我的定位**：**核心开发之一（"初代目"）**，非项目负责人。作为项目早期核心研发，主要负责多个业务分析子 Agent、初版任务调度框架与一批基础服务能力的从 0 搭建。

**我做了什么**：

- 负责渠道、投放、搜索、货品、全域、GMV 等一批**业务分析子 Agent** 的从 0 到 1 建设。
- 搭建**初版调度框架**：并发控制、任务重启 / Kill、优先级调整、动态配置，支撑多用户并发下报告任务的稳定生产。
- 建设**基础服务与工具接入**：服务异步化、鉴权、日志接入、报警，以及多个业务模块的 MCP 工具化接入与报告离线链路。

**结果**：作为部门首款 AI 对客产品如期上线，后续演进沿用了这一版的调度、工具接入与离线链路骨架。

**技术栈**：Python、FastAPI、MySQL、Redis、Kafka、`asyncio`、MCP、LLM Orchestration。
